# 1.0.1 の精細度とメモリ

## 表示の変更

| 対象 | 1.0.0 | 1.0.1 |
|---|---:|---:|
| 全90領域の三角形 | 196,876 | **7,712,880**（元データの全三角形） |
| 概観の枝 | 685,369 | **2,237,417**（同梱523細胞の全枝） |
| 操作中の領域 | 各領域 最大2,200三角形 | 各領域 最大20,000三角形、全体1,613,676 |
| 縦画面の領域配分 | 高さ43%、最大380dp | **20〜85%でドラッグ調整・最大表示** |
| 横画面の領域配分 | 固定比率 | **20〜85%でドラッグ調整・最大表示** |

全ての元の三角形とfloat32化した座標が、公式ファイルと順番まで一致することを
データ検証で確認。法線だけを正規化したsigned byteへ変換している。
神経形態の個別表示と元の523ファイルは変更していない。
全165,122細胞を一度に描画する仕様ではない。

静止時の高精細全脳表示は、実RAMが6GiB以上でLow-RAMでない端末で初期状態から有効。
選択部位は設定にかかわらず元の形状を使う。神経の概観や個別形態の背景は操作用の
軽い領域形状を使い、神経を見分けやすくする。

## メモリの持ち方

- GLES2のuint16索引を使い、同じ頂点を三角形ごとに展開しない。
- 領域は座標float32×3、法線signed byte×4の16byte頂点。
- 1MiBのステージングバッファを再利用し、GPUへ転送後にCPU配列を保持しない。
- 神経の概観は既存の同梱ファイルから読み込み、全枝をGPUへ送る。
  個別の神経を変更した際は前のGPUバッファを解放する。
- 形態のGPUバッファは256MiBを上限とする。領域の読み込みが失敗した場合は軽い形状を使う。
- `largeHeap` は使用しない。変更後のエミュレーターのJavaヒープ上限は192MiB。
- レンダリングは必要時のみ。ドラッグ・ピンチ・領域サイズ変更中は軽い形状を使い、
  指を離すと元の形状を描画する。概観は操作中だけ4細胞に1細胞の表示とし、
  静止後に全523細胞の全枝へ戻す。

## エミュレーターでの測定

Android 15 / API 35、x86_64、SwiftShader、Debug APK、最大表示。
[生の記録](performance/emulator-1.0.1.json)。テスト中の1回のシナリオであり、
端末横断の保証や旧版との統制された速度比較ではない。

| 状態 | GPUの形態バッファ | プロセスPSS |
|---|---:|---:|
| 全90領域の元の形状をロード | 127.7MiB | 268.2MiB |
| 全領域を保持し、概観の全枝もロード | 178.9MiB | 329.2MiB |

`glFinish` を含む静止フレーム時間は全領域で約352〜387ms、概観で約213〜227ms。
これはソフトウェアGPUの検証値で、実機のFPSではない。実機のジェスチャー中の
フレームレートは測定していない。PSSはJavaヒープだけでなく、ネイティブ・共有メモリ等を含む。
GPUバッファ量とは集計方法が異なるため、両者を合計しない。

Pixel 10a（実RAM 7,752,904KiB、Android 17）の署名付きRelease版で、
全7,712,880三角形の描画ログとGPU形態バッファ133,890,152byteを確認した。
更新後の静止状態のPSSは **504,019KiB（492.2MiB）**。
データ消去・実機へのタッチ入力注入は行っていない。
[実機記録](performance/pixel-10a-1.0.1.json) を参照。
DebugのソフトウェアGPU測定と実機のRelease測定は条件が異なるため、速度や省メモリの比較には使わない。

## 配布

高精細モデル約90MB（AAB内圧縮値）を `atlas_models` のinstall-time asset packに分離。
本体の圧縮値は約161MB。インストール後はAssetManagerでオフラインに読み込める。
追加のPlay Core SDKは使用しない。
[Android公式のinstall-time配信の説明](https://developer.android.com/guide/playcore/asset-delivery/integrate-java#install-time-delivery)
に従い、AABの分割インストールと全データ入りuniversal APKの両方を検証する。
